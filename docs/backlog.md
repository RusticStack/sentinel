## Part 25 — GitHub Actions runner mode

Design: [plan 16.10](../plan.md#1610-github-actions-runner-mode). Owner decision of 2026-10-22: migrating from GitHub Actions or Blacksmith is a `runs-on:` change. GitHub orchestrates; Sentinel supplies an ephemeral just-in-time runner per job, running the official `actions/runner` inside its existing sandboxes. Native Actions-syntax execution is out of scope; native `.sentinel.yml` stays the full-speed mode. Taken first after v0.1 and before Part 21. Linux runner mode needs only Parts 04, 05 and 08 (rootless Podman with egress); microVM and Windows labels need Part 23 (M04, M06, M07). Tests on the verification hosts against recorded GitHub fakes; live checks only on the pilot forks.

- [ ] **AR01** Runner permissions and intake: the base App gains Actions read (for `workflow_job`) and `organization_self_hosted_runners` write, or repository `administration` write for personal namespaces (decided 2026-10-22: one App, as Blacksmith's); the controller requests and checks them only for a tenant with runner mode on, and refuses runner-mode setup naming the missing permission; `workflow_job` deliveries (`queued`, `in_progress`, `completed`) through the durable intake with signature check, dedup and audit; label parsing into classes (`sentinel-<n>vcpu-ubuntu-2404`, `-windows-2025`, `-ubuntu-2404-arm`), unknown labels ignored, unbound repositories refused. Gate: cross-tenant and unbound-repository refusals; duplicate and reordered deliveries; removal of the App stops provisioning at once. Depends on G01, G02.
- [ ] **AR02** Demand and provisioning: a `queued` event becomes a Sentinel job of the label's class placed by the existing scheduler; at lease, `generate-jitconfig` (repository or organization endpoint, the binding's runner group, the class labels) and sealed single-use delivery to the worker; demand counted per label set, since GitHub may assign any matching queued job to the runner; bounded reconciliation for missed events and idle runners (de-register, destroy). Decide by measurement whether webhooks plus reconciliation or the scale-set protocol of GitHub's Scale Set Client is the demand source. Gate: a burst of queued jobs gets one runner each; a lost event is recovered within the reconciliation bound; no runner outlives its bound idle. Depends on AR01.
- [ ] **AR03** Linux runner sandbox on rootless Podman: a runner image with the pinned official `actions/runner` (update policy stated: pinned and rebuilt within GitHub's 30-day window, or self-update), started with the JIT configuration, one job, then the sandbox destroyed; `job_network = "egress"` pools; lifecycle and timing recorded, no job output captured. Gate: a pilot workflow job passes on `reference-host` and on `arm64-host` (`-arm`) with only `runs-on:` changed; cancel from GitHub and a worker crash leave no sandbox and no registered runner. Depends on AR02. Partly done: the worker's egress mode (`job_network`, `crates/sentinel/src/service.rs:82`); nothing runner-specific exists.
- [ ] **AR04** Runner in microVMs: Firecracker for Linux, Cloud Hypervisor for Windows guests on `kvm-host`, the guest image with the runner installed; Docker available inside Linux guests for `container:`, `services:` and Docker actions; Windows jobs without nested virtualization (stated). Gate: the pilots' setup actions resolve from the image without downloads where the image carries the version. Depends on AR03.
- [ ] **AR06** Transparent cache and artifacts on local disk (decided 2026-10-22: Blacksmith-fast cache, artifacts never at GitHub): per-sandbox DNS for the Actions cache and artifact service hosts plus a per-sandbox CA trusted only inside the sandbox, terminating TLS at a Sentinel endpoint on the worker host that serves `actions/cache`, the `setup-*` caches and `upload/download-artifact` from Sentinel's cache store and artifact store (E-series), on NVMe, scoped by tenant, repository, trust and platform; implemented from the open-source clients at pinned versions; every other GitHub host passes through; unimplemented calls refused, never forwarded. Depends on AR03, K03, E01.

## Part 21 — Guided GitHub Actions migration

Design: [plan 16.5](../plan.md#165-guided-github-actions-migration). Reworked 2026-10-22 for runner mode (Part 25): the default migration is a pull request that swaps `runs-on:` labels, as Blacksmith's wizard does; generating a native `.sentinel.yml` is the optional "go native for full speed" path per workflow. Deterministic; jobs Sentinel cannot serve stay on GitHub's runners, named with the reason. Exercised on the three pilots only; never on upstream repositories.

- [ ] **H01** Migration permissions on the one App: Contents, Pull requests and Workflows write requested only when a tenant starts a migration, setup refused naming what is missing, withdrawal stopping every write path at once; permission-change lifecycle through the existing intake; personal namespaces supported. Gate: an installation without migration on keeps the base permissions; withdrawal stops writes at once; audit rows. Depends on G01, G05.
- [ ] **H02** Workflow analyzer in `sentinel-pipeline`: bounded YAML (the pipeline loader's limits) over `.github/workflows/*.yml` at a pinned SHA; an inventory of triggers, jobs, matrices, `runs-on`, `uses:` with versions, `container:`/`services:`, secrets/variables referenced, permissions, concurrency, caches, artifacts. A versioned label table maps each job's `runs-on` (GitHub-hosted Ubuntu/Windows, arm64, Blacksmith labels) to a Sentinel label class or keeps it with the reason (macOS, GPU, no matching class, Docker needed where only container workers exist); for the native path a rule table classifies each construct translatable / with a stated change / unsupported. Fixtures: the pilots' workflows at their B01a commits plus malformed and oversized inputs. Gate: no job and no construct classified "unknown" on the fixtures; limits enforced. Depends on C04, AR01.
- [ ] **H03** Change generator and preview API: the default output is the `runs-on:` diff per workflow (only those lines change), with the jobs kept on GitHub listed and their reasons; on request, the native path's deterministic `.sentinel.yml` (and `scripts/ci/` stubs) from the inventory and [recipes](recipes.md), validated by `pipeline validate`, with a job-by-job mapping and the secret names to provision. Gate: the label diff touches no other line; native pipelines validate for every fixture; byte-identical output for identical input. Depends on H02.
- [ ] **H04** Pull request creation and update on a `sentinel/migrate` branch with the App's migration permissions; never a default-branch push; re-running updates the same PR; branch protection respected. Gate: on a pilot fork, create, update and close; refused cleanly without the migration permissions. Depends on H01, H03.
- [ ] **H05** Shadow runs and parity: in runner mode, the PR first adds a non-required copy of each migrated job with its Sentinel label beside the unchanged original, so both run on the same SHAs while GitHub's runners stay authoritative; on the native path, non-required `sentinel / <job>` checks. Per job pair and SHA, conclusions, test counts (JUnit/Go JSON where reported) and durations from the Actions jobs/steps API, p50/p95 with sample counts. Gate: a week of pilot pushes compared; mismatches listed, not hidden. Depends on H04, AR03 (runner mode) or B10's shadow setup (native).
- [ ] **H06** Switch: in runner mode, the PR update that drops the copies and swaps the originals' labels; job names and required checks are unchanged, and Sentinel verifies branch protection is untouched. On the native path, read branch protection and rulesets, preview the exact change, apply only with an extra opt-in permission (otherwise a person applies it and Sentinel verifies), then open the PR disabling the replaced workflow jobs. Gate: settings after the switch equal the preview on each pilot. Depends on H05.
- [ ] **H07** Rollback: one action opens the revert PR (labels back, or workflows re-enabled) and, on the native path, shows (or applies, with the permission) the required-check change back; shadow mode re-enterable; every step audited. Gate: rollback on each pilot restores the pre-switch workflows and settings exactly. Depends on H06.
- [ ] **H08** The wizard in the interface (connect, pick repositories, analysis, preview with diff, PR, shadow parity, switch, rollback; the native path as an option) on Part 20 routes, run end to end on the three pilots; measure time from connect to the first shadow run. Gate: browser test of the flow against a seeded controller and a recorded GitHub fake; the pilot run recorded. Depends on H07, U11.

**Checkpoint:** a repository's Actions CI moves to Sentinel through the interface with a reviewed PR that changes only `runs-on:` (or, by choice, a native pipeline), measured shadow parity, an explicit switch and a tested rollback.
